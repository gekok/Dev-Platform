# Issue #58 — WP1 API contract & dependency register

Ngày khảo sát: 2026-11-08
Checkout: `feature/web-demo-issue-58` @ `9f08b79afd45f774cca38d84de3cfadc881312d9`
Phạm vi: FE `web-demo` và backend/Gateway chỉ để xác định dependency. Đây là đối chiếu source/tài liệu, không phải thiết kế API mới hoặc bằng chứng runtime end-to-end.

## Cách phân loại

- **Source implemented**: có route/controller và use case hoặc persistence implementation liên quan trong source.
- **Partially implemented**: có một phần source, nhưng thiếu use case, dependency, authorization hoặc readiness để dùng theo luồng mục tiêu.
- **Documented only**: contract có trong tài liệu mục tiêu nhưng chưa có route/use case backend tương ứng.
- **Missing in frontend**: chưa có API client/UI cho luồng đó.
- **Runtime verified**: đã kiểm tra với các service và hạ tầng thật. Không có luồng backend nào được xếp loại này trong đợt khảo sát.

## Nguồn xác minh và giới hạn

- Contract ưu tiên theo `docs/README.md`: `docs/project/architecture-decisions.md`, `docs/api/kanban-api.md`, integration checklist, rồi mới đối chiếu source. Các dòng Project-first trong API reference có nhãn target/proposal; không dùng làm bằng chứng runtime.
- FE gọi API qua `web-demo/src/shared/services/axios.js` với base URL cố định `/api/v1` và Bearer interceptor. `web-demo/src/main.jsx` luôn khởi động MSW với `onUnhandledRequest: 'bypass'`; hiện chưa có chế độ Backend tách biệt.
- Frontend calls nằm trong `src/features/{auth,projects,boards,cards,notifications}/services/*Api.js`; hành vi UI/shape tiêu thụ nằm trong hooks/pages/components tương ứng. MSW handlers có thể mô phỏng API nhưng không chứng minh backend route.
- Board preferences có API client/MSW riêng (`src/features/preferences/services/preferenceApi.js`); tài liệu API đánh dấu chúng là demo-only, backend owner/contract chưa chốt. WP5 cần giữ chức năng này trong Demo mode hoặc ẩn/disable ở Backend mode.
- Gateway source có JWT filter và ghi đè `X-User-Id` từ JWT `sub`; tests dùng upstream giả và Redis mock. Các test này không chứng minh snapshot production, direct-service ingress, hoặc service E2E.
- Backend test source hiện có ở user-service, task-service, notification-service và Gateway; không thấy test source ở board-service. Chưa chạy backend tests trong WP1. WP0 chỉ chạy web-demo tests: 82 pass, không có Gateway/backend request thật.
- Vì vậy, **chưa endpoint nào trong danh sách được đánh dấu Runtime verified**.

## Documentation drift / chú ý

`docs/README.md` còn câu mô tả board-service chưa có Project/Membership entity; hiện `services/board-service/src/main/java/.../ProjectEntity.java`, `ProjectMembershipEntity.java`, `InvitationEntity.java` và database docs cho biết các mapping/schema local đã có. Điều này không thay đổi kết luận API: board-service API docs và source vẫn cho biết Project/Membership/Invitation controller/use case chưa hoàn chỉnh. Nên sửa mô tả stale khi cập nhật tài liệu backend, ngoài scope code frontend WP1.

## Kết luận WP1

Register xác nhận FE hiện chủ yếu là Demo/MSW. Login/current account và Notification REST có implementation source; Card/Comment source có nhưng fail-closed theo readiness; Board/Column chỉ còn Board-first skeleton; Project/Membership/Invitation chưa có API backend; event-generated Notification chưa được nối ở Notification listener. Frontend/backend E2E chưa được xác minh. Các API mismatch và service-level blockers được ghi ở bảng trên để làm đầu vào WP2–WP8, không tự chốt contract còn mở.

## Cập nhật trạng thái frontend sau WP2–WP8

Ma trận phía trên ghi nhận audit WP1 tại baseline; các điểm sau cập nhật trạng thái code frontend hiện tại. Đây vẫn là bằng chứng source/test/build, không phải xác minh runtime Gateway/backend.

- **WP2 — runtime/API foundation:** `VITE_APP_MODE` và `VITE_API_BASE_URL` phải khai báo rõ. Demo mới khởi động MSW; Backend không nạp worker và request chưa được MSW xử lý sẽ hiện lỗi. Axios gắn Bearer token và chuẩn hóa lỗi 401/403/network/5xx.
- **WP3 — authentication:** Backend login dùng `POST /auth/login`; current account dùng `GET /users/me`. Session được kiểm tra khi khởi động/refresh; 401 trên request đã xác thực xóa session và cache. Không dùng demo token trong Backend mode.
- **WP4 — Project:** phần UI đọc metadata Project tùy chọn mà backend chưa trả được. Project, Membership và Invitation API vẫn là dependency của board-service; không có fallback mock trong Backend mode.
- **WP5 — Board/Column:** default Board preferences chỉ chạy trong Demo. Backend không gọi preference list/clear/update; selector ẩn nút thay đổi preference. Project-scoped Board list/create chưa được triển khai trong board-service source hiện kiểm tra, vì vậy chưa xác minh được luồng Board Backend.
- **WP6/WP7 — Card/Comment:** Backend mode dựng Project-scoped Task route cho Card detail/create/move/assignment và Comment. Demo giữ nguyên Board-scoped mock routes. Member ID chấp nhận trường `userId` của target summary hoặc `id` của Demo; chỉ trường `fullName` được dùng làm tên hiển thị. Card list Backend chủ động fail closed với `CARD_PAGINATION_CONTRACT_PENDING`, không gọi route Board-first cũ. Infinite scroll chưa triển khai vì cursor query/wire, ordering/move semantics và stale-cursor behavior còn chờ duyệt.
- **WP8 — Notification:** Inbox hỗ trợ lọc unread qua `unreadOnly=true`; query cache được tách theo filter và mark-read invalidates các biến thể của inbox. Event generation vẫn chưa được xác minh end-to-end.
- **WP9/WP10 — errors/tests/docs:** loading/error states, retry có điều kiện, README và test evidence được cập nhật cùng code.

Kiểm tra frontend sau các cập nhật: `npm test` pass **115**, fail **0**, skipped **0**; `npm run lint` pass; `npm run build` và `npm run build:backend` pass. Backend bundle chỉ có entry JS/CSS, không có MSW worker hay demo chunks. Không chạy Gateway/backend E2E; các Project/Board API backend còn thiếu, Task readiness mặc định fail closed và môi trường service chưa được xác minh.
