# Issue #58 — WP1 API contract & dependency register

Ngày khảo sát: 2026-11-08
Checkout: `feature/web-demo-issue-58` @ `9f08b79afd45f774cca38d84de3cfadc881312d9`
Phạm vi: FE `web-demo` và backend/Gateway chỉ để xác định dependency. Đây là đối chiếu source/tài liệu, không phải thiết kế API mới hoặc bằng chứng runtime end-to-end.

Phần kiểm kê đầu tiên bên dưới ghi lại baseline ở commit `9f08b79` trước khi đồng bộ `main`. Các kết luận về trạng thái backend Project/Board trong baseline đã được thay thế bởi mục **Trạng thái sau đồng bộ main**; các giới hạn runtime vẫn còn hiệu lực.

## Cách phân loại

- **Source implemented**: có route/controller và use case hoặc persistence implementation liên quan trong source.
- **Partially implemented**: có một phần source, nhưng thiếu use case, dependency, authorization hoặc readiness để dùng theo luồng mục tiêu.
- **Documented only**: contract có trong tài liệu mục tiêu nhưng chưa có route/use case backend tương ứng.
- **Missing in frontend**: chưa có API client/UI cho luồng đó.
- **Runtime verified**: đã kiểm tra với các service và hạ tầng thật. Không có luồng backend nào được xếp loại này trong đợt khảo sát.

## Trạng thái sau đồng bộ main

Đối chiếu source hiện tại tại nhánh `feature/web-demo-issue-58` sau merge `origin/main` (`fe4376c`). Các route dưới đây có controller và application service trong source; đây không phải bằng chứng chúng đã chạy end-to-end.

## Nguồn xác minh và giới hạn

- Contract ưu tiên theo `docs/README.md`: `docs/project/architecture-decisions.md`, `docs/api/kanban-api.md`, integration checklist, rồi mới đối chiếu source. Các dòng Project-first trong API reference có nhãn target/proposal; không dùng làm bằng chứng runtime.
- FE gọi API qua `web-demo/src/shared/services/axios.js` với base URL cố định `/api/v1` và Bearer interceptor. `web-demo/src/main.jsx` luôn khởi động MSW với `onUnhandledRequest: 'bypass'`; hiện chưa có chế độ Backend tách biệt.
- Frontend calls nằm trong `src/features/{auth,projects,boards,cards,notifications}/services/*Api.js`; hành vi UI/shape tiêu thụ nằm trong hooks/pages/components tương ứng. MSW handlers có thể mô phỏng API nhưng không chứng minh backend route.
- Board preferences có API client/MSW riêng (`src/features/preferences/services/preferenceApi.js`); tài liệu API đánh dấu chúng là demo-only, backend owner/contract chưa chốt. WP5 cần giữ chức năng này trong Demo mode hoặc ẩn/disable ở Backend mode.
- Gateway source có JWT filter và ghi đè `X-User-Id` từ JWT `sub`; tests dùng upstream giả và Redis mock. Các test này không chứng minh snapshot production, direct-service ingress, hoặc service E2E.
- Backend test source hiện có ở user-service, task-service, notification-service và Gateway; không thấy test source ở board-service. Chưa chạy backend tests trong WP1. WP0 chỉ chạy web-demo tests: 82 pass, không có Gateway/backend request thật.
- Vì vậy, **chưa endpoint nào trong danh sách được đánh dấu Runtime verified**.

## Documentation drift / chú ý

`docs/README.md` còn câu mô tả board-service chưa có Project/Membership entity; hiện `services/board-service/src/main/java/.../ProjectEntity.java`, `ProjectMembershipEntity.java`, `InvitationEntity.java` và database docs cho biết các mapping/schema local đã có. Điều này không thay đổi kết luận API: board-service API docs và source vẫn cho biết Project/Membership/Invitation controller/use case chưa hoàn chỉnh. Nên sửa mô tả stale khi cập nhật tài liệu backend, ngoài scope code frontend WP1.

## Kết luận WP1

Kết luận WP1 phản ánh baseline tại `9f08b79`: FE khi đó chủ yếu là Demo/MSW và chưa có Project/Invitation integration. Sau khi đồng bộ `main`, source Board Service đã có Project/Membership/Invitation và Project-scoped Board/Column routes/use cases như bảng cập nhật phía trên. Frontend/backend E2E vẫn chưa được xác minh; Task Card/Comment tiếp tục fail-closed theo readiness (identity gate mặc định tắt) và Notification event generation chưa được nối end-to-end.

## Cập nhật trạng thái frontend sau WP2–WP8

Ma trận phía trên ghi nhận audit WP1 tại baseline; các điểm sau cập nhật trạng thái code frontend hiện tại. Đây vẫn là bằng chứng source/test/build, không phải xác minh runtime Gateway/backend.

- **WP2 — runtime/API foundation:** `VITE_APP_MODE` và `VITE_API_BASE_URL` phải khai báo rõ, mode được chuẩn hóa không phân biệt hoa/thường và phải khớp Vite build mode. Demo mới khởi động MSW; Backend không nạp worker và request chưa được MSW xử lý sẽ hiện lỗi. Axios gắn Bearer token và chuẩn hóa lỗi 401/403/network/5xx.
- **WP3 — authentication:** Backend login dùng `POST /auth/login`; current account dùng `GET /users/me`. Session được kiểm tra khi khởi động/refresh; 401 trên request đã xác thực xóa session và cache. Thay đổi access token ở tab khác cũng xóa cache và đưa route bảo vệ về login. Không dùng demo token trong Backend mode.
- **WP4 — Project:** Backend mode hiện đọc `myRole`, Project list/detail và paged member/invitation responses qua public API; UI có tìm tài khoản, mời/hủy và nhận lời/từ chối invitation. Profile names được nạp qua User Service. Chưa có UI remove/leave membership; runtime chưa xác minh.
- **WP5 — Board/Column:** default Board preferences chỉ chạy trong Demo. Project-scoped Board list/create, Board detail, add Column và reorder Column đã có route/use case trong Board Service source; FE dùng `boardKey`, `{columnIds}` và `PUT /columns/order`, unwrap envelope và nạp page. Backend mode chưa xác minh end-to-end.
- **WP6/WP7 — Card/Comment:** Backend mode dùng Project-scoped Task routes cho Card list/detail/create/move/assignment và Comment. List gọi riêng từng Column với `columnId`, `limit=5`, `cursor`; UI nhận `{items,nextCursor}`, tải tiếp khi cuộn, dedupe Card ID và yêu cầu reload Column khi request cursor tiếp theo trả `400`. Chuyển Card xuống cuối chờ tải trang đầu và toàn bộ trang còn lại; lỗi tải không gửi lệnh move. Thứ tự và move index theo `position DESC, id DESC`. Demo giữ Board-scoped mock routes nhưng MSW mô phỏng cùng page shape, cursor scope, giới hạn trang và move ordering. Member ID chấp nhận trường `userId` của target summary hoặc `id` của Demo; chỉ trường `fullName` được dùng làm tên hiển thị. Đây là frontend/source behavior; Task runtime qua Gateway chưa được xác minh. Card endpoints vẫn fail-closed khi trusted identity gate tắt hoặc snapshot chưa sẵn sàng; khi được bật, Board lookup xác minh quan hệ Project/Board/Column cho create/move.
